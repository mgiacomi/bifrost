## Research Question

Use the `1_research_codebase.md` research command to investigate the Bifrost codebase for PR 13 — Trace Parser, Indexes, and Shared Calculations (`ai/thoughts/tickets/bifrost-console-pr-13-trace-analysis-services.md`). Document what exists today, where it exists, how it works, and how the components involved in trace acquisition, storage, parsing, projection, and fixture validation interact.

## Summary

The codebase already contains the Java trace writer/artifact pipeline and the Go console artifact service from which PR 13 will be built. There is no trace parser, index, or shared calculation service in the current checkout, but the `bifrost-console` artifact layer exposes explicit seams for it.

Key points:

- **Java side**: `bifrost-spring-boot-starter` writes one JSON object per line to an NDJSON trace file. `TraceRecord` is the canonical record type (with 33 `TraceRecordType` values); `DefaultExecutionTraceRecorder` and `DefaultExecutionTraceHandle` append records, chunk large payloads, and finalize with a `TRACE_COMPLETED` record that carries the terminal `sessionUsageSnapshot`. The `/observability/v1/traces/{traceId}/artifact` endpoint streams the file as `application/x-ndjson`. The Java `NdjsonExecutionTraceReader` is the authoritative reference for the streaming parse and chunked-payload reconstruction contract PR 13 must replicate in Go.
- **Fixture corpus**: `bifrost-console-fixtures` contains 18 trace files and 18 matching expected-result files generated by Java. They are the current Java-to-Go semantic contract and include valid cases (success, failure, abort, retry, nested retry, chunked payload, unattributed usage, etc.) and invalid cases (malformed JSON, non-monotonic sequence, inconsistent identity, missing completion, contradictory usage, etc.).
- **Go console side**: `bifrost-console` has a `internal/artifact` package (`Service`, `Lease`, `Handle`, `storage`) that acquires, installs, and pins artifacts. `Service.Use(handle)` issues a `Lease` whose `Open()` method returns an `io.ReadCloser` over the installed NDJSON file. These are deliberately marked as the PR 13 streaming/parser seam. The console service wires the artifact service to observability (for metadata) and the application adapter (for artifact streaming).
- **Live/SSE**: `internal/live` already implements bounded, cursor-based, continuable queries over activity events (not over raw trace records), using `RecentRequest`/`RecentResponse` and a ring buffer. This is the pattern PR 13 should follow for trace-analysis query boundaries.
- **Legacy CLI**: `bifrost-cli/main.go` contains a TUI viewer that loads whole trace files into memory, builds frame trees from `FRAME_OPENED`/`FRAME_CLOSED`, and interleaves records by sequence. Its record-parsing and tree-building ideas may be reused, but the phase documentation explicitly says the new console code must not depend on the CLI project.
- **Framework lens**: Traces are classified as an *ephemeral diagnostic format*. The project does not support historical/cross-version readers, schema migration, or dual record forms unless a future ticket changes that policy.

### 1. PR 13 ticket scope and constraints

The ticket file `ai/thoughts/tickets/bifrost-console-pr-13-trace-analysis-services.md` defines the work.

- **In scope** includes stream-parsing bounded NDJSON, validating identity/ordering/enums/frame relationships/terminal completion, reconstructing logical payloads from envelopes and chunk records, building disk/memory-conscious indexes, calculating duration/usage/retry/attempt attribution, deriving unattributed usage, and adding bounded query/search/range primitives (`ai/thoughts/tickets/bifrost-console-pr-13-trace-analysis-services.md:12-28`).

### 2. Java trace record contract

#### 2.1 Record schema

`com.lokiscale.bifrost.internal.core.TraceRecord` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/TraceRecord.java:14-27`) is the canonical record:

- `traceId` (String, required, non-blank)
- `sessionId` (String, required, non-blank)
- `sequence` (long)
- `timestamp` (Instant, required)
- `recordType` (TraceRecordType, required)
- `frameId` (String, nullable, blank normalized to `null`)
- `parentFrameId` (String, nullable, blank normalized to `null`)
- `frameType` (TraceFrameType, nullable)
- `route` (String, nullable, blank normalized to `null`)
- `threadName` (String, defaults to `"unknown"`)
- `metadata` (Map<String, Object>, unmodifiable copy)
- `data` (JsonNode, nullable, deep-copied)

The `TraceRecordType` enum (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/TraceRecordType.java:3-38`) lists **33** record types (one per line, 5-37), including `TRACE_STARTED`, `TRACE_CAPTURE_POLICY_RECORDED`, `FRAME_OPENED`, `FRAME_METADATA_RECORDED`, `PAYLOAD_CHUNK_APPENDED`, `MODEL_REQUEST_PREPARED`, `MODEL_REQUEST_SENT`, `ADVISOR_REQUEST_MUTATION_RECORDED`, `MODEL_RESPONSE_RECEIVED`, `ADVISOR_RESPONSE_MUTATION_RECORDED`, `MODEL_THOUGHT_CAPTURED`, `PLAN_CREATED`, `PLAN_UPDATED`, `PLAN_VALIDATION_FAILED`, `PLAN_RETRY_REQUESTED`, `PLAN_QUALITY_WARNING`, `TOOL_CALL_REQUESTED`, `TOOL_CALL_STARTED`, `TOOL_CALL_COMPLETED`, `TOOL_CALL_FAILED`, `EVIDENCE_RECORDED`, `EVIDENCE_VALIDATION_FAILED`, `EVIDENCE_VALIDATION_PASSED`, `LINTER_RECORDED`, `STRUCTURED_OUTPUT_RECORDED`, `STEP_STARTED`, `STEP_ACTION_PROPOSED`, `STEP_ACTION_VALIDATED`, `STEP_ACTION_REJECTED`, `STEP_COMPLETED`, `ERROR_RECORDED`, `FRAME_CLOSED`, and `TRACE_COMPLETED`. (An earlier draft of this document reported 38; the live enum has 33.)

`TraceFrameType` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/TraceFrameType.java:3-12`) has `ROOT_MISSION`, `SKILL_EXECUTION`, `MODEL_CALL`, `TOOL_INVOCATION`, `RETRY`, `PLANNING`, `STEP_EXECUTION`.

`TraceOutcome` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/TraceOutcome.java:3-8`) is `SUCCEEDED`, `FAILED`, `ABORTED`.

`UsagePrecision` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/usage/UsagePrecision.java:3-8`) is `EXACT`, `HEURISTIC`, `UNAVAILABLE`.

`ModelUsageRecord` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/usage/ModelUsageRecord.java:1-30`) stores `promptUnits`, `completionUnits`, `totalUnits`, `precision`, and optional `nativeUsage`, with validation that total is at least each component.

`SessionUsageSnapshot` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/usage/SessionUsageSnapshot.java:5-15`) stores 10 counters, including `promptUnits`, `completionUnits`, `usageUnits`, `exactModelResponses`, `heuristicModelResponses`, `unavailableModelResponses`, etc. `recordModelUsage` (`SessionUsageSnapshot.java:81-95`) increments `modelCalls` and the unit/precision counters.

#### 2.2 Recording and finalization

`DefaultExecutionTraceRecorder` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/DefaultExecutionTraceRecorder.java:14-216`) is the main recorder. `recordModelResponseReceived` (`DefaultExecutionTraceRecorder.java:55-60`) records `MODEL_RESPONSE_RECEIVED` with attempt metadata and usage. `finalizeTrace` (`DefaultExecutionTraceRecorder.java:148-152`) delegates to `BifrostSession.finalizeTrace`.

`ModelTraceContext` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/ModelTraceContext.java:1-144`) is call-local model trace state. It:
- Generates a `retrySequenceId` per context (`ModelTraceContext.java:24`)
- Generates sequential `attemptNumber` via an `AtomicInteger` (`ModelTraceContext.java:25`, `60-63`)
- Produces attempt metadata with `retrySequenceId`, `attemptId`, `attemptNumber` (`ModelTraceContext.java:108-114`)
- Adds usage metadata (`promptUnits`, `completionUnits`, `totalUnits`, `precision`) on response (`ModelTraceContext.java:74-84`)
- Validates attempt metadata through `requireAttempt` (`ModelTraceContext.java:116-133`)

`DefaultExecutionTraceHandle` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/trace/DefaultExecutionTraceHandle.java:1-548`) owns the file.
- `finalizeTrace` (`DefaultExecutionTraceHandle.java:264-303`) appends `TRACE_COMPLETED` with completion metadata (outcome, session usage, terminal failure id, errored flag, persistence policy), sets `completed`, and returns a `FinalizedTraceArtifact`.
- `appendInternal` (`DefaultExecutionTraceHandle.java:340-405`) builds a `TraceRecord`, serializes `data` to JSON, and, if the serialized payload exceeds `DEFAULT_CHUNK_SIZE = 4096` (`DefaultExecutionTraceHandle.java:41`), writes an envelope record with `payloadId`, `chunkCount`, `payloadChunked`, `contentType` (set to `text/plain` for textual data or `application/json` for object data, `DefaultExecutionTraceHandle.java:369`), then writes `PAYLOAD_CHUNK_APPENDED` records for the chunks (`DefaultExecutionTraceHandle.java:419-451`). Each chunk record carries `payloadId`, `chunkIndex`, `chunkCount`, `contentType` in metadata and a `TextNode` substring of the serialized payload as `data` (`DefaultExecutionTraceHandle.java:433-447`). The logical record with the full `JsonNode` data is still published to observers (`DefaultExecutionTraceHandle.java:396`).
- `buildRecord` (`DefaultExecutionTraceHandle.java:453-476`) constructs the record, assigning trace/session IDs, the next sequence, the resolved timestamp, frame references, thread name, metadata, and data.
- `readRecords` (`DefaultExecutionTraceHandle.java:322-326`) uses `NdjsonExecutionTraceReader` to stream records back.

`NdjsonTraceRecordWriter` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/trace/NdjsonTraceRecordWriter.java:1-44`) opens the file with `CREATE | WRITE | APPEND`, writes a single JSON object, and then a newline.

`NdjsonExecutionTraceReader` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/trace/NdjsonExecutionTraceReader.java:1-232`) is the Java reference implementation for streaming NDJSON parsing and chunked-payload reconstruction — the closest existing analogue to what PR 13 must build in Go. It is invoked by `DefaultExecutionTraceHandle.readRecords` (`DefaultExecutionTraceHandle.java:322-326`) and consumes records via a `Consumer<TraceRecord>` callback rather than materializing the whole trace. Behavior:

- Reads character-by-character through a `BufferedReader` and accumulates a line buffer, treating both `\n` and `\r\n` as record terminators (`NdjsonExecutionTraceReader.java:41-61`). A trailing line with no final newline is still processed (`NdjsonExecutionTraceReader.java:63-66`).
- Parses each non-blank line as a `TraceRecord` through Jackson (`NdjsonExecutionTraceReader.java:87`). A decode failure on a trailing partial record is swallowed; a decode failure on a full line is rethrown (`NdjsonExecutionTraceReader.java:89-96`).
- Reconstructs chunked payloads through `PendingChunkedRecord` (`NdjsonExecutionTraceReader.java:128-231`): when a record carries `metadata.payloadChunked == true`, it becomes the envelope; subsequent `PAYLOAD_CHUNK_APPENDED` records are appended by `chunkIndex`, the `payloadId` must match, and `chunkCount` must be satisfied. On completion it emits one logical record (envelope with rebuilt `data`) followed by the raw chunk records (`NdjsonExecutionTraceReader.java:183-203`). `rebuildData` honors `contentType`, returning a `TextNode` for `text/plain` and parsing JSON for `application/json` (`NdjsonExecutionTraceReader.java:118-126`).
- A non-`PAYLOAD_CHUNK_APPENDED` record arriving before a pending payload completes is an `IOException` (`NdjsonExecutionTraceReader.java:152-155`); a missing `chunkIndex` is an `IOException` (`NdjsonExecutionTraceReader.java:163-167`); a missing chunk at rebuild time is an `IOException` (`NdjsonExecutionTraceReader.java:222-225`). A still-incomplete payload at EOF is emitted as envelope-plus-available-chunks rather than discarded (`NdjsonExecutionTraceReader.java:67-70`, `:205-213`).

This reader is the authoritative source for the envelope/chunk reconstruction contract PR 13's Go parser must replicate.

`BifrostSession.finalizeTrace` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/BifrostSession.java:703-807`) projects an execution journal from the trace handle, converts projection failures into failed completions with an `ERROR_RECORDED`, calls `handle.finalizeTrace`, and closes the observation handle.

`TraceCompletion` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/core/TraceCompletion.java:1-74`) validates that succeeded traces have no `terminalFailureId` and failed/aborted traces have one. Its `metadata()` method (`TraceCompletion.java:38-68`) produces the map written into the `TRACE_COMPLETED` record, including `outcome`, `sessionUsageSnapshot`, and `terminalFailureId`.

- Validates the request shape with `requireArtifactRequest` (`ObservabilityRestController.java:380-410`): must be `GET`, no query params, no conditional/range headers, and must accept `application/x-ndjson`

#### 2.4 Activity projection

`LiveActivityProjector` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/observation/LiveActivityProjector.java:1-...`) is the source of the SSE activity stream and a good reference for which trace record fields are consumed.
- `VISIBLE` record types (`LiveActivityProjector.java:21-36`) filter which records become activities.
- `DETAIL_KEYS` (`LiveActivityProjector.java:38-42`) include `retrySequenceId`, `attemptId`, `attemptNumber`, `skillName`, `segment`, `planId`, `stepNumber`, `failureId`, `outcome`, `terminalFailureId`, etc.

`ExecutionActivityKind` (`bifrost-spring-boot-starter/src/main/java/com/lokiscale/bifrost/internal/runtime/observation/ExecutionActivityKind.java:1-23`) lists the activity kinds; the Go `live` package mirrors these exactly (`bifrost-console/internal/live/dto.go:17-36`).

### 3. Fixture corpus

`bifrost-console-fixtures/README.md:1-50` describes the corpus as the current-release Java-to-Go semantic contract. `traces/` has the NDJSON files; `expected/` has only the semantic results the Go trace analysis needs: identity, outcome, terminal failure, physical-attempt grouping, validation-to-attempt links, attributed and terminal usage, and the derived unattributed remainder, or one invalidity category.

There are 10 valid and 8 invalid fixtures (as reported by the fixture subagent and confirmed by the file list):

Valid examples:
- `single-attempt-success.ndjson` — one model call, exact usage, succeeded.
- `terminal-failure.ndjson` — one attempt, then a terminal `ERROR_RECORDED`, failed.
- `terminal-abort.ndjson` — no attempts, terminal `ERROR_RECORDED`, aborted.
- `advisor-retry.ndjson` — two attempts with `ADVISOR_*` mutation records, validation passed.
- `nested-retry-sequences.ndjson` — multiple `retrySequenceId`s with nested attempts.
- `validation-exhaustion.ndjson` — retry attempts end with `exhausted` status and terminal failure.
- `nonterminal-error-then-success.ndjson` — a non-terminal `ERROR_RECORDED` followed by a successful model call.
- `chunked-payload.ndjson` — large payload split into `PAYLOAD_CHUNK_APPENDED` records.
- `unattributed-usage.ndjson` — attributed usage (10/4/14) differs from terminal `sessionUsageSnapshot` (13/6/19), giving derived unattributed usage (3/2/5). See `bifrost-console-fixtures/expected/unattributed-usage.json:18-22` and `bifrost-console-fixtures/traces/unattributed-usage.ndjson:1-6`.
- `unavailable-usage.ndjson` — usage precision is `UNAVAILABLE`.

Invalid examples (with the canonical `errorCategory` string each `expected/*.json` carries, defined in `ConsoleTraceFixtureCorpusTest.java:52-60`):
- `malformed-json.ndjson` — not valid JSON. `errorCategory: MALFORMED_JSON`.
- `duplicate-sequence.ndjson` — repeated sequence number. `errorCategory: NON_MONOTONIC_SEQUENCE`.
- `inconsistent-identities.ndjson` — `sessionId` changes mid-trace. `errorCategory: INCONSISTENT_IDENTITY`.
- `missing-completion.ndjson` — no `TRACE_COMPLETED` record. `errorCategory: MISSING_COMPLETION`.
- `non-final-completion.ndjson` — `TRACE_COMPLETED` is not the final record. `errorCategory: NON_FINAL_COMPLETION`.
- `unsupported-enum.ndjson` — unsupported enum value in the outcome field. `errorCategory: UNSUPPORTED_VALUE`.
- `incomplete-chunks.ndjson` — declared `chunkCount` not satisfied. `errorCategory: INCOMPLETE_CHUNKS`.
- `contradictory-usage-reconciliation.ndjson` — session usage totals are internally inconsistent. `errorCategory: CONTRADICTORY_USAGE`.

These eight category strings are the canonical invalidity vocabulary the Go parser must emit to match the fixtures and the ticket's acceptance signals.

The Java test `ConsoleTraceFixtureCorpusTest` (`bifrost-spring-boot-starter/src/test/java/com/lokiscale/bifrost/internal/runtime/trace/ConsoleTraceFixtureCorpusTest.java`) regenerates the fixtures and validates them byte-for-byte against the committed files. It also validates invariants: monotonic sequences (`ConsoleTraceFixtureCorpusTest.java:108`), exactly one terminal `TRACE_COMPLETED` that is also the final record (`ConsoleTraceFixtureCorpusTest.java:109-111`), per-`attemptId` lifecycle order `MODEL_REQUEST_PREPARED → MODEL_REQUEST_SENT → MODEL_RESPONSE_RECEIVED` with positive monotonic `attemptNumber` (`ConsoleTraceFixtureCorpusTest.java:114-141`), and unattributed usage arithmetic (`terminal − attributed`, `ConsoleTraceFixtureCorpusTest.java:184-194`).

### 4. Go console artifact service (PR 13 seams)

### 5. Live/SSE query pattern (model for PR 13 queries)

`internal/live/dto.go:1-184` defines the activity DTOs:
- `ActivityKind` constants (`internal/live/dto.go:17-36`) mirror Java's `ExecutionActivityKind`.
- `Activity` (`internal/live/dto.go:81-96`) carries cursor, session, trace, sequence, kind, frame references, summary, and `json.RawMessage` details.
- `RecentRequest` (`internal/live/dto.go:172-176`) is the bounded query request: `Cursor`, `SessionID`, `Limit`.
- `RecentResponse` (`internal/live/dto.go:178-184`) is the bounded response: `Items`, `HasMore`, `NextCursor`, `Continuity`, `BeginningUnavailable`.
- `Continuity` (`internal/live/dto.go:156-164`) carries interval ID, target scope ID, instance ID, first/last cursor, observed time, and reset facts.

`internal/live/service.go` (`bifrost-console/internal/live/service.go:1-863`):
- Maintains a ring buffer of up to 2,048 entries / 8 MiB (`internal/live/service.go:21-22`), plus subscriber caps of 256 frames / 1 MiB and a recent-query limit of 100 (max 256) (`internal/live/service.go:23-26`).
- `Recent` (`internal/live/service.go:658-729`) implements the bounded, cursor-based query with optional `sessionID` filtering, `hasMore`, `nextCursor`, `continuity`, and `beginningUnavailable`.
- `SubscribeSnapshotAfter` (`internal/live/service.go:762-769`, delegating to `subscribeAfterLocked` at `internal/live/service.go:771-821+`) supports replay and live subscription with overflow detection.
- The worker loop `run` (`internal/live/service.go:207-342`) handles reconnection backoff and scope invalidation; `runBaselineRefresh` starts at `internal/live/service.go:344`.

This is the closest existing implementation of the bounded, continuable, scoped query primitive PR 13 needs for trace records/frames/attempts.

### 6. Legacy CLI trace viewer

`bifrost-cli/main.go:1-1308` is a standalone Bubble Tea TUI that reads `.execution-trace.ndjson` files from a directory.

- `TraceRecord` struct (`bifrost-cli/main.go:86-100`) is the Go on-disk representation. Note it uses `RecordType` and `Data`/`Metadata` as `interface{}` and a calculated `Duration` field, unlike the Java `TraceRecord`.
- `findTraceFiles` (`bifrost-cli/main.go:996-1030`) discovers files named `{session}.{trace}.execution-trace.ndjson`.
- `scanTraceFileSummary` (`bifrost-cli/main.go:1033-1069`) and `loadTraceRecords` (`bifrost-cli/main.go:1071-1089`) use `json.NewDecoder` and `decoder.More()` to read records one at a time, stopping on the first decode error.

### 7. Framework design lens and protected contracts

`ai/thoughts/framework-feature-design-lens.md:23-38` classifies surfaces into:
1. Application API
2. Supported SPI
3. Configuration and manifest contracts
4. Persisted or serialized contracts
5. Ephemeral diagnostic formats
6. Internal or accidentally exposed implementation

Traces are explicitly Category 5 (ephemeral diagnostic formats). The document states:
- Execution traces are current-run debugging tools, not historical analytics, archival, audit, or cross-version interchange formats.
- Trace schemas, record types, field names, storage layout, and projection behavior may change to improve the current tool.
- Do not add legacy readers, schema migrations, version adapters, dual record formats, or historical compatibility fixtures unless a future ticket changes the policy.
- Update or remove obsolete fixtures and compatibility tests atomically.

This means PR 13 can parse the current Java record format and fixture set without providing historical readers, but must update fixtures/tests atomically when the Java contract changes.

The `consoleCompatibilityVersion` in `application-rest/instance-status.json` is the gate for exact-version matching; its current fixture value is `"0.1.0-SNAPSHOT"` (`bifrost-console-fixtures/application-rest/instance-status.json:1`). ### 8. Historical decisions from phase documents

- **Backend-for-frontend, not a second execution engine**: `bifrost_console_phase_2_ui_console.md:71` states the console host is the backend-for-frontend and owner of console-side trace analysis, not another authoritative observability database or execution engine.
- **Browser does not recalculate**: `bifrost_console_phase_2_ui_console.md:81` says the browser owns the in-memory live view but does not parse raw NDJSON or independently calculate hierarchy, duration, usage, failure, or availability.
- **Shared Go services**: `bifrost_console_phase_2_ui_console.md:484-489` says one adapter-neutral Go artifact service is the sole path for acquiring and analyzing finalized traces; browser and MCP call this service.
- **Mechanical calculation definitions**: `bifrost_console_workflows.md:413-422` defines direct usage (activity owned by selected frame, excluding descendants), descendant usage (frames below), inclusive (direct + descendant), attempt usage (usage with a selected `attemptId`), retry usage (sum of attempts sharing a `retrySequenceId`), and unattributed usage (recorded usage not safely assignable to a more specific hierarchy). It also says `attemptId` and `retrySequenceId` are the only identity for attempt/retry membership; adjacency and matching messages are not relationships.
- **Index construction**: `bifrost_console_phase_2_ui_console.md:706-707` says shared Go services calculate `inclusiveDuration` from `FRAME_OPENED`/`FRAME_CLOSED` timestamps and `selfDuration` by subtracting immediate-child inclusive durations, and build settled flat failure and validation reference indexes during parsing.

## Architecture Documentation

- **Record flow (Java)**: `BifrostSession` → `DefaultExecutionTraceHandle.append` → `TraceRecord` → `NdjsonTraceRecordWriter` → local NDJSON file → `ObservabilityRestController.artifact` → `application/x-ndjson` HTTP stream.
- **Record flow (Go, current)**: `applicationclient.OpenArtifact` → `artifact.Service.Acquire`/`installStream` → installed file under `transient/artifacts` → `Lease.Open` → `io.ReadCloser`. No further Go processing exists today.
- **Projected flow for PR 13**: `Service.Use(handle)` → `Lease.Open()` → bounded NDJSON streaming parser → in-memory or on-disk indexes → shared query service for frames, records, attempts, validation links, failures, timing, and usage → browser and MCP adapters.
- **Scope and cancellation**: Target scope `Context` is registered with `context.AfterFunc(scope.Context, cancel)`. On scope rotation, `InvalidateTargetScope` cancels acquisitions, invalidates leases, removes files, and releases capacity. Caller cancellation is mapped to `TARGET_UNAVAILABLE`; scope rotation is mapped to `TARGET_CHANGED`.
- **Bounded query pattern**: `RecentRequest` (cursor, session, limit) → `RecentResponse` (items, hasMore, nextCursor, continuity, beginningUnavailable). PR 13 should reuse this pattern for trace record/result pagination.
- **No full-trace in browser**: The design keeps trace analysis in the Go backend; the browser consumes derived, bounded, continuable evidence queries.
